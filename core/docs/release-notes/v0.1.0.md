# Sofia's Assistant v0.1.0 — MVP Release Notes

**Status:** MVP release readiness (Gate I13 — MVP Ready, SA-B034). This
document describes what the release readiness gate proved. It is not, by
itself, an announcement of public availability — publishing a tag/GitHub
Release is a separate, explicit action.

## What Sofia can do in this release

- **Text Conversation** — authenticated client, durable Conversation/Turn,
  context building, provider-abstracted inference, streaming and
  non-streaming turns.
- **Realtime Voice** — authenticated realtime session over WebSocket, audio
  and transcript lifecycle, barge-in/interruption, canonical Turn recorded
  once the interaction terminalizes.
- **Memory** — cross-conversation recall through the Sofias Memory
  abstraction (remember → recall → context), with recall treated as
  untrusted context that never gains tool/authority capability.
- **Filesystem and Shell** — Tool Registry + Policy + Grant/Confirmation for
  file reads/writes and argv-only (no shell-string) process execution, with
  path canonicalization, workspace bounds, filtered environment, timeouts,
  and bounded output.
- **Web Research** — bounded multi-source research: search, read at least
  two distinct sources, and synthesize an attributed answer. Source
  attribution always reflects what the runtime actually read, never what a
  provider claims to have read.
- **Reminders** — durable one-shot/recurring reminders that survive a Core
  restart, deliver as Notifications, and are retrievable by the client.
- **Delegated Agents** — Sofia/root can create a narrowly-scoped AgentRun
  (reduced context, reduced Tool subset, reduced authority) for a
  specialization such as development-analysis or web-research, with a
  bounded result and full Audit trail.
- **Recovery** — durable Task intent, ToolCall uncertainty classification,
  subprocess start evidence, AgentRun interruption semantics, and authority
  recalculation on restart, so interrupted work is neither silently lost nor
  silently duplicated.
- **Audit** — every authorized action and Policy decision is recorded and
  queryable, with secrets and credentials redacted.
- **Desktop Client** — a PySide6 desktop client that authenticates to a
  local Core over loopback HTTP/WebSocket.

## Architecture and security boundaries (unchanged by this release)

- `AI proposes -> Runtime authorizes -> Executor acts`. A provider or a
  recalled Memory item can request an action; it never authorizes one.
- Localhost-only authentication for the Core HTTP/WebSocket boundary; the
  Core is not exposed on the LAN by default.
- Every protected side effect passes through Policy before execution; Grants
  narrow authority to an exact capability/resource scope and never widen it
  across a Task/Agent boundary.
- Shell execution is always explicit executable + argv, never a shell
  string.
- Web reads are SSRF-guarded (no loopback/private/link-local/metadata
  destinations by default) and bounded in size and redirect count.
- Secrets are only ever read from `SecretService` (backed by Windows
  Credential Manager); no API key is ever read from `.env` or committed to
  the repository.
- Configuration never implicitly discovers a `.env` file in production; an
  env file is only used when a caller explicitly opts in.

## Setup essentials

```powershell
cd core
uv sync
copy .env.example .env   # optional: non-secret local configuration
uv run python -m sofias_assistant.secrets set integrations/sofias-memory/api-key
```

The desktop client is a separate process from the Core; it connects to a
running Core over `--core-url` (default `http://127.0.0.1:8989`).

## Optional external services

- **Sofias Memory** — optional. Disabled unless a base URL is configured;
  its absence or an outage degrades Memory to `DEGRADED`/`UNKNOWN` health
  without preventing Core startup or blocking conversation.
- **OpenAI (text/realtime)** — real provider adapters exist and have
  historical live-smoke evidence from earlier Slices; the default release
  test suite runs entirely against deterministic fakes and needs no network
  access or billing.

## Recovery guarantees

- Durable Task intent survives a crash before execution starts.
- An uncertain ToolCall is reconciled from evidence on restart; a mutating,
  non-idempotent call is never blindly retried.
- A subprocess's PID is recorded as evidence only — recovery never adopts or
  kills a process it did not start.
- A stale AgentRun from a lost runtime session is interrupted, not silently
  resumed.
- Authority is recalculated (not replayed) on restart; recovery can never
  grant more than the current, live authorization state allows.

## Known limitations

- No standalone Core server launcher/console script yet. `SofiaCore` +
  `LocalClientBoundary` composition is proven end-to-end by integration
  tests (see `tests/integration/client_boundary/test_core_http_adapter.py`
  and `tests/integration/core/test_core.py`); wiring a real provider (e.g.
  OpenAI) and the local HTTP boundary into one long-running process is
  currently a manual composition exercise, not a packaged entry point.
- `ToolExecutionMode.SANDBOX` remains fail-closed (`SANDBOX_UNAVAILABLE`);
  there is no sandboxed execution backend in this release.
- No universal exactly-once execution guarantee: recovery avoids duplicating
  *critical* side effects and never silently loses durable intent, but it is
  not a distributed exactly-once transaction system.
- No general-purpose/universal workflow engine — Tasks and Agents are
  bounded, specialized flows, not an arbitrary orchestration platform.
- No plugin marketplace in this MVP (`SA-B032 Plugin Foundation` remains
  deferred, post-kernel, optional).
- No wake word or continuous camera/microphone perception — voice
  interaction is explicit session-based (open/close), and Vision only
  observes a single bounded, explicitly captured image at a time.
- Web Research is intentionally bounded (small, fixed limits on search
  results considered, sources read, and evidence size per source) rather
  than a general-purpose autonomous browsing agent.

## Deferred

- `SA-B032 Plugin Foundation` — deferred, post-kernel, optional for the
  first MVP release.
